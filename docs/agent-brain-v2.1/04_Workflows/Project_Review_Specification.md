# Project Review — Alignment, Quality & Readiness

## Boundary
Project Review is a separate Atlas workflow from MAAP Review. The canonical diagram explicitly includes both. Project Review focuses on project alignment, quality and readiness. Its formal methodology, rubric, owners and cadence are to be confirmed; do not invent a corporate scorecard.

## Proposed configurable domains
- Strategic/scope alignment: objectives, scope, deliverables, change requests, assumptions and stakeholder alignment.
- Delivery quality: quality criteria, acceptance, defects/rework, operational stability, documentation and handover.
- Execution health: milestones, dependencies, capacity, blockers, decisions and delivery predictability.
- Client alignment: feedback, expectations, communication, satisfaction evidence and unresolved concerns.
- Team/capability readiness: roles, skill coverage, dependencies, onboarding and continuity.
- Risk/readiness: open risks, mitigations, go-live/transition readiness, support model and next milestone.
- Actions/decisions: accountable owner, due date, priority, decision log and escalation.

## Atlas conversation
Opening: “I'd like to understand how the project is progressing—not just whether tasks are on track, but whether we're still aligned on the outcome, quality and what needs to happen next.”

Open questions:
- “How well does the current delivery still match the original objective?”
- “What has changed in the scope or assumptions since kickoff?”
- “Where are you seeing the strongest evidence of quality?”
- “What is creating rework or uncertainty?”
- “What would need to be true for the next milestone to be considered ready?”
- “Which risks need a decision rather than another status update?”

## Workflow
Trigger → load project facts and latest approved evidence → gather delivery owner/team/client feedback where permitted → Atlas identifies gaps and prepares a review brief → project owner validates facts → review decisions/actions recorded → owners assigned → follow-up checkpoint → close with versioned outcome.

## Guardrails
Do not infer quality solely from delivery sentiment. Missing project data is not a failed project. Preserve dissenting views and source links. Project Review cannot automatically change MAAP outcomes, consultant skill levels or employment status. Project Review does not authorize a Spotlight story.
