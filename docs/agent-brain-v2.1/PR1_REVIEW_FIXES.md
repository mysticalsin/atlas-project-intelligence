## Changes and regression evidence

| Finding | Change | Regression coverage |
|---|---|---|
| P1: superseding a withheld detail restores its private utterance | Withholding is read from the append-only detail history independently of `active`. Transcript/report redaction, analyst context exclusion and rejection of model attempts to re-file private words all retain that choice. The Python ledger and analyst match the edge behavior. The original source and withheld flag remain in the owner-only audit/checkpoint. No format migration is needed. | `session-summary.test.js`: withhold, supersede, serialize/restore, attempt to re-file, build a later analyst prompt, end and inspect report input/final transcript. `test_quality.py` covers the Python path; `summary.test.js` checks inactive withheld quotes. |
| P1: an abandoned interview overwrites the replacement checkpoint | The Durable Object rotates checkpoint ownership before starting the replacement, including after the existing 3-second suspension timeout. Store mutations share a queue; queued stale saves/purges are rejected, ownership is checked again after reads, and an already issued write finishes before the next owner mutates storage. Concurrent upgrade requests cannot install an older replacement last; stale message handlers cannot dispatch into an abandoned session. | `worker-interview.test.js`: hold an old analyst past the suspension deadline, start/checkpoint the replacement, release the old work, and attempt its cleanup. A separate overlapping-upgrade case verifies newest-window ownership. `checkpoint.test.js` holds both metadata reads and already-issued writes. |
| P2: reconnect waits forever for ready | Every reconnect attempt has a 60-second opening/readiness deadline, matching the initial handshake. Timeout, send failure, pre-ready socket error and server refusal settle the attempt and close its socket. Successful ready clears the timer. Late events from abandoned sockets cannot be accepted. Existing three-attempt backoff and saved-interview retention remain. | `voice-reconnect-dom.test.js`: sockets open without ready; all three attempts finish, every stalled socket closes, the microphone stops and the checkpoint is not discarded. Existing resume/refusal/cancel tests remain. |
| P2: summary refresh loses a typed correction | The editor retains text, focus, selection and selection direction while the same detail remains reviewable. Save and Cancel clear its local draft explicitly. Confirm asks the person to save or cancel an open correction first. | `summary-card-dom.test.js` exercises a late update while typing, saving the retained words, and the confirm guard. `humane_browser.py` repeats text/focus/selection preservation in Chromium. |
| P2: incomplete confirmation visibility | Revalidation found that the newer branch already binds a draft to the shown detail IDs and seals the ledger on confirmation. However, the server still showed only 40 details, the browser was capped at 60, and quotes were clipped. The card and browser now expose all 100 possible ledger details and their complete validated quotes (up to 1,800 characters). Spoken recaps keep their separate short limits. The private draft and separate explicit Submit action are unchanged. | `session-summary.test.js` compares the 100 reviewable IDs and complete last quote with the actual saved draft input. DOM and Chromium tests inspect and operate on the 100th item. Existing sealed-ledger, withheld-item, owner-only and separate-submit tests remain. |
