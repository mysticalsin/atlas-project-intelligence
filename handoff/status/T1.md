### Decisions and deviations (each recorded for the integration review)
- **Placeholder sharing is exact, not case-insensitive.** §2.3 says identical spans share a placeholder "compared case-insensitively". Done that way, "ZEBRACORP" typed after "Zebracorp" was shown back to the author as "Zebracorp": a visible case change only for library names. That is a membership oracle, which ground rule 5 forbids. Spans now share a placeholder only when identical, and are stored exactly as typed, so `unmask` returns the author's text unchanged. The model may see two placeholders for two spellings.
- **Other view = `forOthers(recordText(value))`** in `bidView` (§3 writes `forOthers(value)`). This also masks a real library client name that a model produced on its own, for every non-author. Placeholder text is otherwise unchanged.
- **`bidView(lib, user, bidId)` returns a renderer function** `render(value)` with `render.view = 'author' | 'other'`. The author is the owner or an admin while `pseudo` is not NULL. A missing or purged bid renders the other view; it never throws.
- **`getRequirement`** throws `fail(404)` for a non-author, an unknown bid or an unknown requirement. It returns copies: `{bid: {id, owner, alias, prospects: string[]}, requirement: {id, text, kind, must}, pseudo: {…}}`.
- **libraryNames cache key** adds `SUM(revision)` to `COUNT(*)` and `MAX(updated_at)`, so two saves in the same millisecond still invalidate it.
- **Scale.** A single alternation regex took about 27 s for 5,000 names over a 60,000-character brief. The matcher now indexes names by first word and uses one sticky regex per name, with the same semantics: 3 ms (compile 230 ms, cached per library change). `test/scrub.test.js` "scale" guards it.
- **Phones.** 7+ digits with `+ ( ) - .` or spaces; ISO dates and year ranges (`2019-2024`) are excluded. Grouped figures such as "1 200 000" are masked as `[phone]`: over-masking, the safe side.
- **STOPLIST** has 868 words (spec: about 500). It includes common-word company names (total, orange, apple, shell, delta…) and first names that are words (will, mark, grace…).
- **Stub return types.** `resolveForInterview` and `fetchWinHint` are `async` and resolve to `null`, so `Session`'s `.then` never throws. `gapNotes → ''`, `gapStatus → []`, `gapGuidance → null`, `timePlan → null`, `verifyBotActivity` async `null`. `teamsRoutes` answers 503 `{error, status: 'BLOCKED_EXTERNAL', reason, needs}`.
- **`review.js` and `reuse.js`** keep their own local `str`: the §6.2 single-copy move is scoped to `library.js`.

### Decisions and deviations (steps 1-4)
- **The author view only un-masks.**
  - Model output is passed through `recordText` BEFORE it is stored (requirements, customer, match text, one-pager text).
  - `bidView`'s author renderer is then `unmask(stored, map)`, while the other view stays `forOthers(recordText(stored))`.
  - Applying `recordText` at read time (§3 as written) would mask a name the author typed once that name later joins the library. That is a visible membership trace, which ground rule 5 forbids.
  - The author view of a model output is still `unmask(recordText(output), map)`, fixed at write time.
  - No other track called `bidView` yet.
- **PII before the own-client scrub** in `recordView`, `snippetsOf` and `safeSummary`. This was a bug found by the new tests: `forModel` turned "ops@brightwave.example" into "ops@the client.example" and split URLs.
- **Placeholder indices are not figures.** In `parseOnePager`, the "1" in "[Company 1]" is ignored by the number check; otherwise titles and claims naming a masked company were blanked or dropped.
- **Malformed entries count as no answer.** In `parseRerankStrict` and `parseBidRank`, entries at 30+ that all lack `why` return `null` (a malformed answer), not `[]`.
- **SafeSummary without full access** also clears `client` and record-masks title, headline, practice, industry, service lines and technologies (Q7). Country is left raw.
- **`BidReference.by`** is the email only for reviewers and admins. Everyone else sees `'you'` or `'a colleague'`, so no `@` reaches a public reader.
- **Purge scope.** Delete also nulls `outcome_note` (free text that may name the prospect). After a purge, requirements edits, match and one-pager answer 409; use and outcome still work (F7). Delete is idempotent.
- **Module-local 404s.** Unknown sub-paths under `bids`, `ask` and `wins` answer 404 from the module, never the generic `/:id` routes. `use` requires references that are visible and published.
- **JEV wiring.**
  - The fetcher is injectable through `lib.services.fetch` (tests); production uses global `fetch`.
  - `today` comes from `lib.now()`, so freshness is deterministic.
  - Stories are built from `recordView` plus `candidateCard` sections.
  - jev.py's `eligible` check is not ported: callers pass only published, visible references, and the §F1.5 story shape has no such flag.
  - The rest is parity-tested, including Python round-half-even.
- **Win loop thresholds.** "Overall decided ≥ 10" counts distinct decided bids, while rates are computed per use. The cache key is stricter than §F7.1: it adds a rowid-weighted checksum of outcomes. The winloop helpers are READY-gated like T3's claims helpers.
- **Industry boost (bids).** A 0.05 boost applies when the row's sector's first word appears in a `sector`-kind requirement. Empty library, or nothing above the floor, gives coverage `unmet` with no suggestions.
- **`fileName`.** Accepted within the F1.2 bounds and never stored (file names often carry the client).
